# 价格与加工费计算

## 两种物品价格

- `autoPrice`：配方推导出的单件价格，包含此前半成品价格和当前工序加工费。
- `manualPrice`：人工覆盖单价，存在时优先参与后续计算。
- 有效价格为 `manualPrice ?? autoPrice`，零价格有效。
- “基础食材”标签成员作为经济系统的外部价格锚点，当前人工定价表见[基础食材定价基准](pricing-baseline.md)。

## 输入与输出

输入和附加物按有效单价乘实际数量求和；无价格物品忽略。标签输入采用标签内最低有效成员价格。多种输出先按物品种类分配，同一种再按数量分配；手动价输出先从可分配总价中扣除。

## 工作方块加工费

属于名称去除首尾空格后等于“工作方块”的标签的物品，才会应用默认加工费。

```text
原始加工费 = 固定费 + 输入总价 × 费率
实际加工费 = 设置上限 ? min(原始加工费, 上限) : 原始加工费
配方可分配总价 = 输入总价 + 实际加工费
```

加工费按整批收取，批量产出会摊薄单件固定费用。配方可分别覆盖固定费、费率和上限。

当前工作方块默认费用采用固定费为主、低比例费并设置批次上限的方案。简单切配最低，常规烹饪居中，发酵和酿造最高；完整参数见[基础食材定价基准](pricing-baseline.md)。

## 反向计算

仅在一个普通输入、没有标签输入且输出存在多个普通物品时反推。无上限时：

```text
输入总价 = max(0, (输出总价 - 固定费) / (1 + 费率))
```

有上限时先验证未封顶解；若加工费已封顶，则使用 `max(0, 输出总价 - 上限)`。再扣除已知附加物总价，剩余部分分给唯一输入物品。
