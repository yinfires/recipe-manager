# 维护记录

## 2026-10-02（裂隙维度餐厅主线设计稿）

- 新增 `docs/mainline-progression.md`，记录裂隙维度餐厅的 0–5 星主线、六座功能岛、NPC、特殊顾客、口味周、品质、腐烂和传送阵解锁规划。
- 明确 0 星基础菜为米饭、煎蛋、烤马铃薯；根据正式 JSON 校验，米饭使用汤锅，煎蛋和烤马铃薯使用炒锅。
- 明确烤马铃薯虽名称含“烤”，仍作为 0 星基础菜使用，不绑定后续烤炉；烤炉仅按正式配方工作方块在 1 星后开放。
- 验证命令：`npm run classify-foods`、`npm run check-food-classification`、`npm test`、`npm run build`、`git diff --check`。
- 迁移注意：烤马铃薯的正式工作方块从烤炉调整为炒锅，分类明细已按正式 JSON 重新生成；不涉及旧存档字段迁移。

## 2026-09-30（水果标签调味汁修正）

- 柠檬汁、青柠汁等作为调味料时不再触发“水果”标签；水果标签仅由成品名称或主体水果原料触发。
- 柠汁腌鱼、酸柠腌虾新增“不含水果”边界断言，并同步更新分类文档。
- 验证命令：`npm run classify-foods`、`npm run check-food-classification`、`npm test`、`npm run build`、`git diff --check`。

## 2026-09-30（分类规则全面修正）

- 全量重构成品菜分类脚本的肉食、素食和米面判定：取消“非肉即素食”互补逻辑，排除蛋类误判肉食，并将米面限制为米饭、粥、面条、米粉和餐食面皮，面包、蛋糕、饼干、派等烘焙品不再标记米面。
- 主类判定改为结合成品名称、核心配方原料、工作方块和最终形态；薯条、炸春卷、烤红薯、烤马铃薯及凉菜、冷切菜、手卷、饭团、臭豆腐、豆包饭按餐食属性归主食。
- 羊羹、幻昙花羹归点心且不再标记汤羹；汤羹仅用于实际汤、粥、咸羹、浓汤或汤煲。明确甜口饮品允许同时拥有“甜”和“甘”。
- 分类脚本继续直接读取当前正式 JSON 的 291 项成品菜并同步维护双向标签引用和自动生成的 `docs/food-classification.md`，不引入逐物品分类副本；鲶鱼烤串未恢复。
- 验证命令：`npm run classify-foods`、`npm run check-food-classification`、`npm test`、`npm run build`、`git diff --check`。

## 2026-09-30

- 分类同时检查成品名称、直接配方原料和工作方块；柠汁腌鱼、酸柠腌虾因使用炒锅不标记生食，茶壶成品使用“茶饮”，酒水区分甘、辛、苦且不与甜、辣混用。
- 新增可重复运行的 `scripts/apply-food-classification.mjs`，同步维护 `item.tags` 和 `tag.items`，生成完整分类明细，并提供 `npm run classify-foods` 与 `npm run check-food-classification`。
- 新增 `docs/food-classification.md` 并写入项目 `AGENTS.md` 永久维护准则；后续新增、修改或删除成品菜、配方、工作方块或标签时必须同步维护该文档。
- 保留用户已删除“鲶鱼烤串”的正式数据变更；分类映射、标签成员、维护文档和测试均不再包含该物品。
- 新增正式数据完整性测试，覆盖唯一主类、双向标签引用、非成品菜隔离及炸春卷、炒锅腌鱼、寿司、奶茶和茶饮等边界样例。
- 分类脚本不使用逐物品静态映射文件；每次直接读取当前正式 JSON 的成品菜、配方和工作方块，避免人工改动数据后产生第二数据源不一致。
